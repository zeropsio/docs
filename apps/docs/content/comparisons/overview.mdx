Zerops, Railway, Render, Heroku, and Fly.io all solve the same problem: run your code without managing raw servers. They differ in how much of the machine you can reach, how pricing is structured, and what stays free after you get past day one.

This section is a straight comparison, not a sales pitch. Where a competitor is genuinely stronger, we say so. Use the [quick answers](#quick-answers) below, skim the [at-a-glance table](#at-a-glance), or open a platform-specific page for the full breakdown.

## What this section covers

Each comparison page looks at the same dimensions so you can judge platforms side by side:

- **Pricing model:** seat fees, workspace tiers, per-second vs per-minute compute, and what you pay at small scale
- **Containers and SSH:** full Linux access vs a more locked-down runtime
- **Infrastructure:** owned bare metal vs capacity layered on a major cloud
- **Free tiers and trials:** what still exists in 2026, and what was removed
- **Managed services:** databases, storage, and how they connect on the private network

## How Zerops differs

Across these comparisons, a few differences show up repeatedly:

### Full Linux containers with SSH

Every Zerops container is a full Linux environment via [Incus](https://linuxcontainers.org/incus/). You can SSH into any running service. Railway added SSH in 2025. Render, Heroku, and Fly.io still use more restricted runtime models.

### Bare-metal infrastructure

Zerops runs on its own bare metal AMD EPYC hardware, not resold AWS or GCP capacity. Railway also runs on owned hardware (Railway Metal). Render, Heroku, and Fly.io sit on major cloud providers or their own fleets with similar abstractions on top.

### Pricing without seat fees

Zerops bills compute **per minute**, with no seat fee and no platform minimum beyond the project core. The others mix plan fees, seat charges, workspace tiers, or usage credits in different ways. Details live on each comparison page.

### Managed services on one private network

Databases, caches, search, queues, and storage run as first-class managed services on the same private network as your app, addressed by hostname (for example `db`). See [Project & Services Structure](/features/infrastructure) and [Internal access](/references/networking/internal-access).

## Quick answers

<FAQ>
  <FAQItem question="Is Zerops cheaper than Railway, Render, Heroku, or Fly.io?">
    It depends on the workload. All five platforms bill differently: flat plans, per-second usage, or a mix. Zerops has no seat fees and no platform minimum beyond the project core, and bills compute per minute. Check each comparison page for how the others structure pricing.
  </FAQItem>
  <FAQItem question="Does Zerops give you SSH access like a VPS?">
    Yes. Every Zerops container is a full Linux environment via Incus, and you can SSH into any running service. Railway added SSH in 2025. Render, Heroku, and Fly.io still run more restricted container models without general SSH into production instances.
  </FAQItem>
  <FAQItem question="Is Zerops built on AWS?">
    No. Zerops runs on its own bare metal AMD EPYC hardware. Railway also runs on owned hardware (Railway Metal) rather than reselling AWS or GCP. Render, Heroku, and Fly.io run on major cloud providers or their own infrastructure layered with similar abstractions.
  </FAQItem>
  <FAQItem question="Which of these platforms still has a free tier?">
    Render keeps a limited free tier for small services and static sites. Railway offers a one-time trial credit rather than an ongoing free plan. Heroku removed its free tier in November 2022. Fly.io removed its permanent free allowance in 2024 and replaced it with a short trial. Zerops has a free lightweight project core; you pay only for the resources you actually run.
  </FAQItem>
  <FAQItem question="When should I pick Fly.io instead of Zerops?">
    When multi-region latency is a hard requirement. Fly.io runs Machines across 30+ regions and is built for edge proximity. Zerops focuses on a fully managed single-region platform experience with managed services, SSH, and simpler operational defaults. See <a href="/comparisons/zerops-vs-flyio">Zerops vs Fly.io</a>.
  </FAQItem>
  <FAQItem question="Is Heroku still a good long-term choice?">
    In February 2026, Salesforce confirmed Heroku is moving to a sustaining-engineering model: security and stability fixes continue, but no new features are planned and no new Enterprise contracts are being written. That matters if you need an actively developed platform. See <a href="/comparisons/zerops-vs-heroku">Zerops vs Heroku</a>.
  </FAQItem>
</FAQ>
