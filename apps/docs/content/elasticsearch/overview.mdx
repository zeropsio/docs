## Connection Details

- **Port**: 9200
- **Protocol**: HTTP only
- **Internal Access**: `http://{hostname}:9200`
- **Basic auth security**
    - **User**: `elastic`
    - **Password**: randomly generated during service creation, find under **Access Details** in service detail

#### Example
```sh
curl -u elastic:generatedpassword http://elasticsearch:9200
```

## Rotating secrets

[Rotating secrets](/features/env-variables#rotating-secrets) describes when and how to rotate, and what to do when it goes wrong. This section covers what is specific to Elasticsearch.

### What is rotated

- The password of the `elastic` user: the `password` variable.
- The passwords of the built-in users `kibana_system`, `logstash_system`, `beats_system` and `apm_system`. They get the same new value.

`connectionString` holds no password and doesn't change.

Users that you created yourself keep their passwords. API keys and tokens are not part of the rotation.

### During the rotation

| | Single-node | HA |
|---|---|---|
| Elasticsearch | keeps running | keeps running, the cluster stays formed |
| Requests with the old password | are refused with `401` | are refused with `401`, on all nodes at once |

### Good to know

- **The rotation needs some extra memory for a moment.** Zerops tries to add RAM to the service before the rotation, and the extra RAM is released again afterwards. This only works if the [maximum RAM](/features/scaling#minimum-and-maximum-ram) of the service leaves room for it. Several rotations in a row add up.
- **Raise the maximum RAM before you rotate.** Ideally set it well above the current usage of the service for the rotation, so that Elasticsearch does not run out of memory. You can lower it again afterwards.
- **API keys and tokens created earlier stay valid.** Revoke them yourself if they may have leaked.
- **A password that you set yourself for a built-in user is replaced.** After the rotation `kibana_system`, `logstash_system`, `beats_system` and `apm_system` all use the value of the `password` variable.
- **The rotation also works after you changed the `elastic` password by hand.** The password doesn't have to match the `password` variable.
- **The health status of the service can show as failing for a short time.** It recovers when the containers receive the new variable.

## Configuration Options

### Plugin Management

You can configure Elasticsearch plugins using a comma-separated list in the service's environment variables:

```yaml
vault:
  PLUGINS: "analysis-icu,ingest-attachment"
```

**Plugin Configuration Details:**
- Defines plugins to install at service startup
- **Format**: `plugin1,plugin2,...`
- Service automatically installs specified plugins during initialization
- Removing a plugin from this list triggers uninstallation on service restart

### JVM Heap Allocation

Control the JVM heap size as a percentage of container memory:

```yaml
vault:
  HEAP_PERCENT: "75"
```

**Heap Configuration Details:**
- Value represents the percentage of container memory allocated to JVM heap
- **Default**: 50% of available container memory
- **Valid range**: 1-100
- To increase available memory, adjust the service's RAM allocation in scaling configuration

:::note Requires Restart
Changes to HEAP_PERCENT require a service restart to take effect.
:::

## Example Configuration

```yaml
services:
  - hostname: elasticsearch
    type: elasticsearch@8.16
    mode: HA
    vault:
      PLUGINS: "analysis-icu,ingest-attachment"
      HEAP_PERCENT: "75"
```
